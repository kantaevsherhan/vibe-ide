# VibeIDE 0.2

## Исполнение и проверка задач

Владелец проекта выбирает исполнителя, модель и рассуждение. Задача поступает из панели Agents или Chronos. В настройках Chronos можно сохранить те же параметры для импорта.

POST /api/agents/tasks принимает параметры запуска и необязательного CLI-проверяющего. Сервер сохраняет параметры с задачей. При успешном завершении он добавляет проверку в ту же очередь одной записью. При ошибке или отмене исполнитель остаётся доступен для повтора. Проверка имеет собственные лог и статус и может быть повторена отдельно. WebSocket сообщает о постановке и завершении обеих задач.

Проверяющий получает исходный запрос и итог исполнителя. CLI запускается в режиме ревью с ограничением прав. Пользователь видит замечания и решает, какие исправления запускать.

## Пользователь и доступ

Владелец рабочей среды входит через существующую сессию. Настройки, файлы и агенты доступны после входа. CLI выполняется от пользователя backend. Контейнер использует пользователя node. Модель API получает запрос и файл контекста проекта. Ключи провайдеров хранятся на backend и скрыты в ответах настроек.

## Основные сценарии

- Открыть проект, редактировать файлы, пользоваться Git и терминалом.
- Отправить задачу Codex CLI или Claude Code CLI и проверить результат в логах и Git diff.
- Подключить Ollama или совместимый API для текстовых запросов.
- Импортировать технические задачи Chronos и получать Telegram-статусы.
- Запланировать короткий ежедневный запрос к выбранным CLI.

## Выполнение

Задачи сохраняются перед запуском. Для проекта выполняется один процесс. Ошибка одной задачи позволяет перейти к следующей. Отмена сначала записывается на диск и затем останавливает процесс. Повторный запуск активного процесса возвращает 409. После перезапуска backend незавершённые задачи получают ошибку, ожидающие продолжаются.

Записи очереди и сессий сериализованы внутри backend и сохраняются через временный файл с переименованием. Для одной рабочей среды запускается один backend.

## Chronos

MCP-клиент использует существующие инструменты chronos_list и chronos_upsert. Поле project должно совпадать с папкой проекта, а заголовок должен содержать [vibe]. Импорт имеет постоянный ключ по идентификатору задачи. Результат процесса записывается в data.vibeide. Статус review означает, что владелец может проверить изменения и завершить задачу в Chronos.

Версия updatedAt передаётся при каждой записи. Конфликт требует следующего чтения. Истёкший токен, недоступный сервер или отсутствие права записи видны в настройках. Фоновая проверка повторяется каждую минуту.

## Расписание

Время вычисляется в выбранном IANA-часовом поясе. Один агент получает один запрос за локальную дату в выбранном проекте. Дедупликация сохраняется в очереди. Пропущенное время после выключения компьютера пропускается. Запросы используют read-only sandbox Codex или отключённые инструменты Claude. Провайдер определяет расход и восстановление лимитов.

## API и события

Все перечисленные маршруты требуют входа.

| Метод и путь | Результат |
| --- | --- |
| GET /api/agents | Четыре поддерживаемых подключения |
| POST /api/agents/tasks | Создание задачи |
| POST /api/agents/tasks/:taskId/cancel | Отмена |
| POST /api/agents/tasks/:taskId/retry | Повтор |
| GET /api/settings | Настройки со скрытыми ключами API и Chronos |
| PUT /api/settings | Проверка и сохранение настроек |
| GET /api/settings/automation | Время и результат последней проверки |
| POST /api/settings/automation/check | Проверка сохранённых настроек |
| WS /ws/agents | snapshot, agent_task, agent_status, agent_output |

Ошибки валидации возвращают 400, отсутствующие проекты и задачи возвращают 404, конфликт активного запуска возвращает 409.

## Следующие решения владельца

Для живого подключения нужны токен Chronos, настройки Telegram и установленные авторизованные CLI. Папка проекта и выбранные агенты задаются в интерфейсе. Поддержка API сейчас включает текстовый ответ в логе задачи. Для изменения файлов используются CLI.
